# Agent instructions for node-minecraft-protocol

## Read first

Read [CONTEXT.md](CONTEXT.md) before changing protocol behavior, and read [SECURITY.md](SECURITY.md) before handling authentication, encryption, session data, packet captures, or untrusted network input. Use [docs/README.md](docs/README.md) and [docs/API.md](docs/API.md) for public behavior and API details. The project follows the shared [PrismarineJS contribution guide](https://github.com/PrismarineJS/prismarine-contribute).

## Repository conventions

- The npm package is named minecraft-protocol. Its runtime entry point is src/index.js and TypeScript declarations are in src/index.d.ts.
- docs/README.md is the canonical README. The root README.md is ignored and is generated by prepublishOnly; do not maintain a second hand-edited copy.
- Version support is declared in src/version.js. Keep the default version, supported list, and minecraft-data protocol registry aligned.
- Protocol schemas and serializers are distributed across src/datatypes, src/transforms, src/client.js, src/server.js, and the protocol data consumed from minecraft-data.

## Safe change rules

- Preserve backward compatibility for every version in src/version.js. Add an explicit version guard or feature capability when wire behavior differs.
- Treat framing, compression, encryption, authentication, and packet-size limits as security boundaries. Reject malformed or oversized input early and keep maxPacketSize limits effective for both clients and servers.
- Keep credentials, access tokens, session responses, private packet captures, and server secrets out of fixtures, logs, examples, and commits.
- When a schema changes, add a targeted round-trip or cycle test and a regression test for the affected version. Do not weaken parser validation to accept malformed input without documenting the reason.
- Prefer changes in minecraft-data or the serializer source over patching a generated fixture. Check whether a packet definition is generated before editing it.

## Commands and completion

The package requires Node.js 22 or newer. From the repository root:

    npm install
    npm run lint
    npm test

npm test runs the Mocha suite through the lint pretest hook. npm run mochaTest runs only the Mocha command. npm run prepublishOnly copies docs/README.md to the ignored root README.md.

Before handoff, run git diff --check, review supported-version changes, and check that packet fixtures contain no secrets. Use the smallest relevant test command for a protocol change and record it in the change description.
